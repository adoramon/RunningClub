# 东成西就

东成西就跑团的原生微信小程序。它服务于一个封闭跑团：成员先用历史艺名完成唯一认领，再查看跑量、提交上月运动截图、接受管理员审核，并持续公开公积金收支。

当前代码对应 **v1.3.14 候选版**，用于上传微信体验版和提交审核。

## 已实现能力

### 成员与权限

- 微信昵称、头像授权后才能继续使用；未授权不进入正式功能。
- 仅历史艺名库中的成员可认领身份；同一艺名只能绑定一个微信账号。
- 已认领成员优先展示微信昵称和头像；未认领成员仅展示历史艺名。
- 管理员仅限“高翔”和“元”。管理员权限始终由云函数二次校验，前端显示不构成授权。
- 提供隔离的“微信审核员体验入口”：审核员完成昵称、头像授权并输入临时审核码后，只能访问固定演示数据，不能读取或修改真实跑团数据。

### 看板与历史分析

- 首页展示上一个完整月的团队实际跑量、总承诺、成员提交情况、达成率排名与公积金提示。
- 跑团累计跑量以历史底表为基础，实时合并管理员已审核通过的截图跑量；同一成员同一月份使用最终审核值覆盖历史空值或旧值，不重复累计。
- 历史数据覆盖跑团既有成员和月度记录；历史“收/交 XX 元”按既定连续未达标规则倒算等效跑量，同时保留原始记录。
- 点击排行榜成员可查看个人分析：历史月历宫格、累计跑量、累计公积金贡献、最近两年跑量趋势和月度激励评价。
- 个人分析以历史底表为基础，并实时叠加管理员已通过的截图跑量及已确认的公积金/请假结算，确保概览、累计值、趋势图与月历使用同一最终口径。
- 历史数据中的成员尚未加入、未提交数据、管理员确认的提前请假、已缴公积金等状态会区别展示；只有管理员审批形成请假结算的月份才标记“提前请假”。

### 截图提交与审核

- 成员每次可提交 1 至 3 张上一个完整月的运动截图。
- 超长手机截图会在上传前等比缩小，在保持文字可读的同时为视觉模型预留足够输出空间，避免模型只返回不完整代码块。
- 步行、健走和散步不参与等效跑量；包含多个月份的汇总截图只读取目标月份，明确标注的月度骑行汇总即使判断模型超时也可安全提取，单次明细不会被自主累加。
- 云函数调用视觉模型识别跑步、骑行、游泳、跳绳和爬升；服务端统一换算为等效跑量，成员可逐项核对、修改或取消计入。
- 管理员可查看原截图、修正数据、通过或作废提交；截图通过云函数换取短期访问链接，任一管理员均可复核；任一管理员通过即生效。
- 成员取消识别、撤回待审核提交或管理员作废时，相关云端截图立即删除且不可恢复；有效历史截图仅保留最近三个提交月份，跑量、审核状态等结构化记录长期保留。
- 对上月未提交、未达标的成员，管理员可设为提前请假或确认已缴公积金；应缴金额由服务端按连续未达标次数计算。
- 成员确认截图后，系统一次性生成并保存阶段性运动评价；重复浏览不会重复调用模型。
- 管理员审核通过后，该成员已保存的阶段性评价会展示在个人分析页，所有已认领跑团成员均可查看；审核中的评价仅本人可见。

### 公积金公示

- 主页提供“公积金收支公示”入口，所有已认领成员可查看当前余额、累计缴入、累计支取、最近月逐笔明细和按年展示的历史月度收支。
- 历史总账已完成对账：`期初 102.00 + 累计缴入 15,437.00 - 累计支取 15,796.00 = -257.00`。
- 逐笔缴入优先展示为“缴纳公积金 / 昵称或艺名缴纳”；支出保留用途备注；金额统一采用千分位格式。
- 仅管理员可提取公积金；金额、用途和可用余额均由服务端校验，提取后自动生成公开流水。

## 跑团规则

- 每名成员承诺月跑量；首次未完成按缺口 `3 元/公里` 缴纳公积金，连续未完成依次为 `6、9……元/公里`；完成后连续次数重置。
- 骑行距离 ÷ 3、游泳距离 × 5、跳绳次数 ÷ 100、爬升米数 × 0.02，均换算为等效跑步公里数。
- 截至 2026 年 7 月，历史公积金余额为 `-257.00` 元；后续只以已确认流水持续累计。

完整字段和规则见 [领域模型](docs/domain-model.md)。

## 技术架构

- 客户端：原生微信小程序。
- 后端：微信云开发 CloudBase，环境 `cloud1-d3gu11p800a6f5c2a`。
- 数据：历史成员、历史月度记录、用户绑定、截图提交、月度结算、公积金流水与月度评价。
- AI：视觉模型仅用于用户主动上传的运动截图识别；文本模型仅接收结构化跑量摘要生成评价。密钥仅存云函数环境变量，不进入客户端或 Git。

核心云函数包括：`get_current_user`、`claim_historical_identity`、`get_historical_dashboard`、`ocr_activity_screenshot`、`submit_activity_screenshot`、`review_activity_submissions`、`cleanup_activity_evidence`、`generate_monthly_evaluation`、`manage_fund_ledger` 和 `claim_review_access`。

## 微信审核与体验

1. 先在微信公众平台确认“小程序类目”和“用户隐私保护指引”已配置，且与小程序内 [隐私政策页](pages/privacy/privacy.wxml) 一致。
2. 上传本候选版后，在“版本管理”中选择该开发版本提交审核。
3. 审核备注应说明：小程序为封闭跑团，正式成员需历史艺名认领；审核员请从注册页进入“微信审核员体验入口”，用临时审核码查看隔离演示数据。审核码仅在本次审核期间提供，审核通过后应立即更换或清空。
4. 审核通过后，再在“版本管理”选择发布；发布前再次核验云函数环境变量、管理员身份和历史账本余额。

本次版本的能力范围和审核说明见 [v1.2.0 发布说明](docs/releases/v1.2.0.md)。

## 边界与注意事项

- 真实历史成员、运动截图和公积金流水属于跑团内部数据，不能导出到公开仓库；公开代码只保留结构、迁移逻辑和脱敏说明。
- 模型识别结果永远需要成员确认与管理员审核；模型输出不能直接进入公积金结算。
- 不要部署旧的 `update_profile` 自由昵称演示函数，它不符合封闭成员准入规则。
