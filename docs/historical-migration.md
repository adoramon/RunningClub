# 历史台账迁移与艺名认领

## 目标

将 `东成西就历史数据.xlsx` 全量保存为可追溯的历史资料，并将其中的艺名作为封闭注册白名单。

## 导入内容

- 历史艺名：一行一个成员，保留 Excel 行号。
- 历史月份：保留工作表中每一个月度列组；缺失月份不补造。
- 历史月度记录：每位成员、每个现有月份一条，保留承诺与实际两个原始单元格值、解析结果和单元格位置。
- 公积金文字：`收 XX 元` 与 `交 XX 元` 都保存为原始值及解析金额，统一归类为公积金记录。
- 基准余额：创建一笔 2026-07、金额 `-257.00` 的历史结转流水。

## 认领规则

- 艺名精确匹配（仅忽略首尾空格）。
- 一个艺名只能绑定一个微信用户；绑定不可由普通成员自行修改。
- 已绑定用户再次登录时直接读取自己的身份，不可选择其他艺名。
- 不匹配、已占用或未认领用户均不能看到跑团业务数据。

## 导入校验

导入完成后必须核对：艺名数量、月份数量、成员月份记录数量、`交/收` 公积金文本数量，以及 2026-07 的结转余额。原始 Excel 永远保留，数据库不作为唯一原始凭据。

## 控制台导入方式

迁移数据由 `scripts/build-history-jsonl.mjs` 生成 UTF-8 JSON Lines 文件。对每个目标集合点击“导入”，选择 JSON 格式和 `Upsert` 模式；依次导入 `historical_members`、`historical_monthly_records`、`history_import_batches` 与 `fund_ledger`。这避免依赖云函数的在线测试时限。
