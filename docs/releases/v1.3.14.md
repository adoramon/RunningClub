# 东成西就 v1.3.14 发布说明

## 版本定位

`v1.3.14` 是当前面向跑团体验与微信审核的候选版。正式成员通过历史艺名完成唯一认领；微信审核员使用隔离演示入口，不能读取或修改真实跑团数据。

## 已实现能力

- 封闭成员准入：微信昵称、头像授权，历史艺名模糊建议、精确认领及唯一绑定。
- 真实历史看板：上月团队完成情况、达成目标排名、公积金提醒、历史累计跑量和趣味里程对比。
- 个人跑量分析：最终审核数据覆盖历史底表，展示概览、累计跑量、累计公积金、最近两年趋势、月度评价和年历宫格。
- 截图识别：一次上传 1 至 3 张上月截图，视觉模型逐图 OCR，文本模型判断目标月份数据，服务端执行单位白名单和等效跑量换算。
- 成员核对：逐项修改、取消计入、取消识别、撤回待审核提交并重新上传。
- 管理员复核：查看原图、修改数据、通过或作废；任一预设管理员处理即生效。
- 月度管理：对上月未提交成员确认提前请假，对未达标成员确认公积金到账，并按连续未达标规则计算金额。
- 公积金公示：当前余额、累计缴入、累计支取、最近月逐笔明细、历史月度收支宫格及管理员用途化支取。
- 数据保护：取消、撤回或作废时立即删除截图；有效截图只保留最近三个提交月份，结构化审核和账本记录长期保留。

## v1.3.11 至 v1.3.14 重点修复

- 长截图上传前限制为最长边 1800px、约 160 万像素，并增强模型 JSON 包装解析，避免视觉输入挤占全部输出空间。
- 步行、健走和散步在服务端硬过滤；判断模型超时时，只允许从目标月份标准卡片提取明确月度汇总，不自主累加单次明细。
- 首页累计跑量实时合并管理员最终审核值；同一成员同一月份覆盖历史底表且不重复累计，审核数据变化会立即穿透旧缓存。
- 个人历史月历不再把空白月份推断成请假；只有管理员形成 `monthly_settlements.status=leave` 的月份显示“提前请假”，其他空白月份显示“未提交数据”。

## 截图识别边界

- 支持跑步、骑行、游泳、跳绳和累计爬升；步行不计入，其他运动当前不自动换算。
- 含多个月份时只读取目标月份；有月度汇总时优先月度汇总，没有月度汇总时把截图视为一次运动，不对多条明细自主求和。
- 卡路里、步数、时长、心率等非距离数据不能计入跑量；登山或徒步只取明确标注的累计爬升米数。
- AI 结果必须经过成员确认和管理员审核，不能直接改变公积金账本。

## 微信审核体验路径

1. 打开小程序并进入注册页。
2. 点击“微信审核员体验入口”。
3. 授权昵称和头像，输入本次审核专用临时审核码。
4. 查看固定演示看板、成员分析和流程样例。

审核码仅配置在云函数环境变量 `RUNNING_CLUB_REVIEW_ACCESS_CODE` 中，不得写入源码、公开说明或截图。审核结束后应立即更换或清空。

## 发布前核对

- 微信公众平台的小程序类目和用户隐私保护指引已配置，并与小程序内隐私政策一致。
- `ocr_activity_screenshot`、`submit_activity_screenshot` 和 `generate_monthly_evaluation` 的云函数超时均为 60 秒。
- AI 地址、模型名、密钥和审核码仅存在云函数环境变量。
- `activity_records`、`monthly_settlements`、`fund_ledger` 等业务集合保持客户端不可直接读写。
- 公积金账本满足：`期初 102.00 + 累计缴入 15,437.00 - 累计支取 15,796.00 = -257.00`。
- 真机复核身份认领、截图识别与撤回、管理员审核、个人分析和公积金公示主链路。

## 已知边界

- 当前上传和结算对象固定为上一个完整月，不处理本月尚未结束的数据。
- 模型识别可能超时或误读，因此所有结果均保留成员核对与管理员复核环节。
- 正式跑团数据只对已认领成员开放；审核入口始终使用隔离演示数据。
